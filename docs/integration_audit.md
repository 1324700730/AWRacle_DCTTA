## AWRaCLe interfaces

- `net/model.py`: `AWRaCLe(decoder=True)` is a Restormer-like encoder/decoder. `forward(inp_img, context_embs)` concatenates the degraded and clean support tensors on batch, encodes with CLIP, captures CLIP visual transformer block 11 `ln_2` output (768-D token sequence), splits support embeddings into degraded/clean halves, then uses `InContextExtBlock` cross-attention in decoder levels 3/2/1. The test API supplies `[degraded_context, clean_context]`.
- `TestDataset_IC` in `utils/dataset_utils.py` crops query and GT to a multiple of 16 and independently resizes each support image to 224 with BICUBIC interpolation, center-crops, converts to tensor, and applies CLIP mean/std normalization. It samples a support pair from JSON unless an explicit pair is passed. `test.py::test_ds` calls the model as `net(degrad_patch, [degrad_context, clean_context])`. The new runner uses the same BICUBIC pipeline.
- Checkpoints are Lightning dictionaries with `net.` prefixes. Original test entry loads `Model.load_from_checkpoint`; the new loader strips that prefix and requires a complete state match. Original test uses CUDA and metrics `compute_psnr_ssim`; SSIM/PSNR are evaluation-only.
- BatchNorm is not apparent in AWRaCLe's restoration model. CLIP is in eval mode when `net.eval()` is used. Dropout was not found in the inspected forward architecture. DCE/CF here refer to the paper's context extraction/fusion concepts; source has `InContextExtBlock`, `ContextAttention`, `CrossAttention`, and projected context fusion rather than modules literally named DCE/CF.
- AWRaCLe includes CLIP and context-fusion parameters absent from PromptIR. The implemented mapping freezes CLIP and selects top-level `prompt*`, `encoder_level*`, and `decoder_level*` parameters; only direct leaf `weight`/`bias` tensors enter Adam, matching DCTTA `collect_params`. Other restoration stages and CLIP remain frozen. Smoke evidence records exact selected tensor names and counts.

## DCTTA code behavior (implementation, not paper paraphrase)

- `train_test_promptir.py` constructs `PromptIR(decoder=True)`, loads `pretrain/model.ckpt`, sets `origin_model=deepcopy(model)` (not subsequently used in the shown loop), configures prompt/encoder/decoder trainable parameters, builds the optimizer, and invokes `compute_fisher` before per-image adaptation.
- `tta.py::SRTTA` deep-copies the student into `model_teacher`, detaches teacher parameters, and uses EMA decay 0.45 after each adaptation iteration. It does not restore student from the initial checkpoint between each query in the outer script; weights persist sequentially across the test loader. The optimizer and teacher also persist. This is stream adaptation, not per-query reset.
- DIR obtains an eight-view flip/rotation teacher pseudo-target (four repeats in `airnet==0` branch), estimates pixel confidence from view variance, and applies weighted L1 + frozen VGG perceptual + wavelet-frequency L1 consistency to student predictions on the original and regenerated degraded input. `teacher_weight` defaults to 5. Target/GT is not used in this loss.
- TRG is `ResidualDiffusionModel` in `RDDM/net.py`; it is not loaded from a pretrained generator checkpoint. `Degradation(opt)` constructs one RDDM/Trainer before the test stream; each call to `gene_net.train(input, target, name)` performs five online updates on the same generator/optimizer state using the teacher pseudo-target, then samples the generated second degraded input. The trainer resets only its step counter between calls. It is neither random noise nor a fixed pretrained degradation operator. The new `OnlineResidualDiffusionTRG` matches this five-step loop, RAdam, gradient clipping, divided loss, stream-persistent weights/optimizer, and sampling current weights after the source Trainer synchronizes EMA for test.
- TIPS in actual code is Fisher-like protection: `compute_fisher` accumulates squared gradients of restoration self-consistency between transformed output and a detached multi-view pseudo-restoration; selects top `fisher_ratio` entries (default 0.6) per parameter tensor; `fisher_restoration` restores selected entries to the initial state after each update. It is not a layer selector that freezes the other 40%; the other entries are allowed to update. It iterates the supplied loader's samples but only uses degraded inputs in the shown function; GT is unpacked and not used. It also allocates an Adam optimizer locally but performs backward without stepping it. Potential code hazards: `loss_t` is unbound if `teacher_weight<=0`; Fisher indexing/shape and parameter matching are based on trainable parameters; `Fisher` return variable is undefined after logging in the shown tail and should be checked before reuse.
- The active `tta.py::compute_loss2` imports `PerceptualLoss` from `utils/loss_utils.py`, which uses pretrained VGG19 at feature layers `[2,7,16,25,34]`; the separately declared VGG16 loss in `train_test_promptir.py` is not used by this TTA loss. Wavelet weights are loaded from a hard-coded path with basename fallback. Its prompt-specific selection `['prompt','encoder','decoder']` and `model(...)[0]` branches are incompatible with AWRaCLe's tensor output and required support-context argument. The new implementation maps prompt/encoder/decoder names, always supplies the same Support pair, freezes CLIP, and uses the existing tensor output directly.

## Integration plan and current boundary

- The new project contains an exact copy of the AWRaCLe model source and a minimal baseline inference entrypoint. It references source checkpoints and datasets in place, without copying large artifacts.
- Support is explicit degraded/clean paths and passed identically to every AWRaCLe teacher/student call. The runner defaults to `seen_pool` and requires an exact pair match in a `split=train` manifest; target-paired support requires the explicit `few_shot` protocol. Optional Query GT is consumed only after restoration for metrics; it is never passed to Fisher-TIPS, TRG, or DIR. Component smokes use a separately labeled Rain100H target-paired fixture and are mechanics checks only.
- The run order matches `train_test_promptir.py`: compute Fisher from a shuffled unlabeled Query pool; adapt sequentially over a second seeded shuffle with persistent student, teacher, TRG and optimizer state; then run final evaluation in sorted filename order using the final adapted student. This preserves the source loader's shuffle semantics while recording exact orders. A fresh process loads the original checkpoint for an independent domain run. This is transductive target-domain adaptation, not independent per-image reset.
- The new project contains the DCTTA RDDM network source with only unavailable/unused training-framework imports removed; `adaptation/trg.py` reproduces its online five-update RAdam loop and DDIM generation without writing through the original Trainer’s hard-coded output paths. TRG and Fisher-TIPS have bounded GPU component smoke evidence. DIR uses the original VGG19 feature loss and local wavelet MAT; a one-Query integrated GPU smoke passed with the user-supplied official VGG19 weights, including Fisher, teacher pseudo-labeling, one student/EMA update, and five-step TRG. Baseline strict checkpoint load and one-query source/new parity have passed; full-resolution and multi-query stream checks remain open.
